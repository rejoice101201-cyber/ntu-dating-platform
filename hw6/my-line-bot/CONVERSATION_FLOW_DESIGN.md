
### 2.6 其他問題分支（LLM 處理）

**觸發方式**：
- 點擊「其他問題」按鈕
- 無法匹配任何關鍵字的訊息
- 複雜問題需要上下文理解

**處理流程**：
```
使用者訊息
  ↓
檢查速率限制
  ├─ 超過限制 → 降級到腳本回應
  └─ 未超過 → 繼續
      ↓
取得對話歷史（最近3-5輪）
      ↓
構建 LLM Prompt
      ↓
呼叫 Gemini API
      ├─ 成功 → 回覆使用者
      └─ 失敗 → 降級到腳本回應
          ↓
      友善錯誤訊息
```

**LLM 回應範例**：
```
使用者：「我臉上長了很多痘痘，該怎麼辦？」

AI 回應：
「您好，關於青春痘的問題，木木日安有提供
專業的青春痘治療服務。

由於每個人的膚質和狀況不同，建議您預約
看診，讓醫師為您進行專業評估，並提供最
適合的治療方案。

如需預約，請致電 02-2778-7178
營業時間：週一至週五 09:00-18:00

木木日安祝福您！💙」
```

## 三、對話狀態管理

### 3.1 狀態定義
```typescript
type ConversationState = 
  | 'idle'                    // 初始狀態
  | 'greeting'                // 歡迎訊息
  | 'menu_selection'          // 選單選擇
  | 'clinic_info'             // 診所資訊
  | 'service_info'            // 服務項目
  | 'appointment_reminder'    // 預約提醒
  | 'appointment_confirm'     // 確認到診
  | 'appointment_cancel'       // 取消預約
  | 'appointment_policy'      // 預約政策
  | 'post_treatment_care'     // 術後照顧
  | 'faq'                     // 常見問題
  | 'symptom_consultation'     // 症狀諮詢（LLM）
  | 'human_transfer'          // 轉接人工
  | 'ended';                  // 對話結束
```

### 3.2 狀態轉換圖
```
                    [使用者加入]

                      idle
                         ↓
                    greeting
                         ↓
                 menu_selection
                         ↓
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
   clinic_info    service_info    appointment_flow
        ↓                ↓                ↓
       end              end         appointment_confirm
                                         ↓
                                    appointment_policy
                                         ↓
                                        end
```

## 四、關鍵字匹配優先級

### 4.1 匹配策略
1. **精確匹配**（最高優先級）
   - 完全符合關鍵字
   - 例如：「地址」→ 診所資訊腳本

2. **部分匹配**
   - 訊息中包含關鍵字
   - 例如：「請問地址在哪裡」→ 診所資訊腳本

3. **同義詞匹配**
   - 使用同義詞庫
   - 例如：「怎麼去」=「地址」=「在哪裡」

4. **無匹配**（最低優先級）
   - 使用 LLM 生成回應

## 五、特殊情況處理

### 5.1 使用者連續快速發送訊息
```
處理策略：
1. 檢查速率限制（1分鐘內最多3次）
2. 超過限制 → 使用腳本回應
3. 未超過 → 正常處理
```

### 5.2 使用者傳送圖片/貼圖
```
處理策略：
1. 記錄事件（儲存到資料庫）
2. 回覆：「抱歉，我目前只能處理文字訊息。
          如需協助，請用文字描述您的問題。」
3. 提供選單按鈕
```

### 5.3 LLM API 失敗
```
處理策略：
1. 捕捉錯誤（429、超時、其他）
2. 降級到腳本回應
3. 回覆：「抱歉，系統暫時無法處理您的問題。
          請致電 02-2778-7178 與我們聯繫。」
4. 提供選單按鈕
```

### 5.4 使用者詢問價格/費用
```
處理策略：
1. 關鍵字匹配：價格、費用、多少錢
2. 回覆：「關於治療費用，會因個人狀況和選擇的療程而有所不同。
          建議您預約看診，讓醫師評估後提供詳細的費用說明。
          
          如需預約，請致電 02-2778-7178」
3. 不提供具體價格（避免誤導）
```

### 5.5 使用者詢問折價券/優惠
```
處理策略：
1. 關鍵字匹配：折價券、優惠、折扣
2. 回覆：「木木日安會不定期推出優惠活動和折價券。
          詳細優惠資訊請致電 02-2778-7178 或關注我們的官方帳號。
          
          治療當日請出示折價券訊息，提供核對查詢。
          本券限本人使用，無法轉讓。」
```

### 5.6 使用者詢問陪同人員
```
處理策略：
1. 關鍵字匹配：陪同、家屬、可以帶
2. 回覆：「館內為維護隱私與靜謐，接待空間僅限接待治療者本人，
          陪同家屬請就近至附近咖啡館或是百貨散步逛街。
          
          感謝您的配合與理解！」
```

### 5.7 使用者詢問症狀/診斷（醫療相關）
```
處理策略：
1. 關鍵字匹配：症狀、問題、怎麼辦、需要
2. 使用 LLM 處理，但必須在回應中：
   - 強調不能提供診斷
   - 建議預約看診
   - 提供診所電話
3. 回應範例：
   「關於您的問題，由於每個人的狀況不同，
    建議您預約看診，讓醫師為您進行專業評估。
    
    如需預約，請致電 02-2778-7178
    營業時間：週一至週五 09:00-18:00」
```

### 5.8 使用者傳送空白訊息或無意義訊息
```
處理策略：
1. 檢查訊息長度（< 2 字元）或只有符號
2. 回覆：「抱歉，我沒有理解您的問題。
          請選擇以下服務，或重新描述您的問題：
          [提供選單按鈕]」
```

### 5.9 使用者長時間未回應（30分鐘以上）
```
處理策略：
1. 下次使用者發送訊息時，重置對話狀態
2. 重新顯示歡迎訊息和選單
3. 不清除對話歷史（保留在資料庫）
```

### 5.10 使用者重複詢問相同問題
```
處理策略：
1. 檢查對話歷史（最近 3 輪）
2. 如果發現重複問題：
   - 使用相同腳本回應
   - 加上：「如果您還有其他問題，請告訴我。」
3. 避免重複呼叫 LLM
```
