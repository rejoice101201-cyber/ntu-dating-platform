# Facebook OAuth 設定詳細步驟

## 當前狀態

從你的截圖可以看到：
- ✅ 你已經在 Facebook Login 的設定頁面
- ✅ 在「有效的 OAuth 重新導向 URI」區域已經有 `http://localhost:3000/api/auth/callback/facebook`
- ❌ 但系統顯示「此重新導向 URI 對此應用程式無效」

## 修復步驟

### 步驟 1: 確認 URI 已正確添加

在「有效的 OAuth 重新導向 URI」文字區域中，確認：
1. URI 是：`http://localhost:3000/api/auth/callback/facebook`
2. **沒有多餘的空格或換行**
3. **沒有引號**（不要加 `"` 或 `'`）
4. 每個 URI 一行（如果有多個）

### 步驟 2: 檢查相關設定

在「用戶端 OAuth 設定」區域，確認以下開關：

#### 必須開啟的設定：
- ✅ **用戶端 OAuth 登入**：必須是「是」
- ✅ **網路 OAuth 登入**：必須是「是」

#### 建議設定：
- **對重新導向 URI 使用 Strict 模式**：
  - 如果開啟（是）：URI 必須完全匹配
  - 如果關閉（否）：允許部分匹配
  - **建議先關閉（設為「否」）**，測試成功後再開啟

- **強制採用 HTTPS**：
  - 開發環境（localhost）建議設為「否」
  - 生產環境必須設為「是」

### 步驟 3: 儲存設定

1. 確認所有設定都正確後
2. **向下滾動頁面**
3. 找到頁面底部的 **「儲存變更」** 或 **「Save Changes」** 按鈕
4. **點擊儲存**

### 步驟 4: 驗證 URI（可選）

1. 在「重新導向 URI 驗證程式」區域
2. 確認輸入框中的 URI 是：`http://localhost:3000/api/auth/callback/facebook`
3. 點擊 **「檢查 URI」** 按鈕
4. 應該會顯示「此 URI 有效」或類似的成功訊息

### 步驟 5: 等待生效

Facebook 的設定變更可能需要幾秒到幾分鐘才會生效。儲存後：
1. 等待 30 秒
2. 重新整理頁面
3. 再次檢查 URI 是否有效

## 常見問題

### Q: 已經添加了 URI，為什麼還是顯示無效？

**A**: 可能的原因：
1. **沒有儲存**：添加後必須點擊「儲存變更」按鈕
2. **Strict 模式**：如果開啟了 Strict 模式，URI 必須完全匹配（包括大小寫、斜線等）
3. **HTTPS 強制**：如果開啟了「強制採用 HTTPS」，localhost 的 HTTP 會被拒絕

### Q: 應該開啟還是關閉 Strict 模式？

**A**: 
- **開發階段**：建議關閉（設為「否」），比較寬鬆
- **生產環境**：建議開啟（設為「是」），更安全

### Q: 應該開啟還是關閉「強制採用 HTTPS」？

**A**:
- **開發環境（localhost）**：必須關閉（設為「否」），因為 localhost 使用 HTTP
- **生產環境**：必須開啟（設為「是」）

## 推薦設定（開發環境）

為了讓 localhost 能正常運作，建議設定如下：

```
✅ 用戶端 OAuth 登入：是
✅ 網路 OAuth 登入：是
❌ 強制採用 HTTPS：否（開發環境必須關閉）
❌ 對重新導向 URI 使用 Strict 模式：否（開發階段建議關閉）
```

## 測試步驟

設定完成後：

1. **儲存所有變更**
2. **等待 30 秒**
3. **清除瀏覽器 cookies**（特別是 localhost 相關的）
4. **重新啟動開發伺服器**（如果還在運行）
5. **嘗試 Facebook 登入**

## 如果還是不行

請檢查：
1. 是否真的點擊了「儲存變更」按鈕？
2. URI 是否完全正確（複製貼上，不要手動輸入）？
3. 「強制採用 HTTPS」是否已關閉？
4. 等待幾分鐘後再試（Facebook 設定可能需要時間生效）
